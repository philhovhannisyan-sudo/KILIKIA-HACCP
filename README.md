# HACCP Suite

Веб-приложение управления пищевой безопасностью (ХАССП, ISO 22000:2018, ISO/TS 22002-1, BRCGS) для производителя джемов, варенья и конфитюров.
26 модулей в 5 группах; требования — [`docs/00-brief.md`](docs/00-brief.md), план — [`docs/01-plan.md`](docs/01-plan.md), статус приёмки — [`docs/03-acceptance.md`](docs/03-acceptance.md).

> Текущее состояние: **фаза 9 — финальная приёмка** — к данным, ролям, журналу аудита и панели готовности (фаза 2) добавлен модуль **A01 «Конструктор плана ХАССП»**: мастер из 7 экранов (12 шагов Codex), схема процесса с перетаскиванием, анализ опасностей, дерево решений ККТ, категоризация OPRP, утверждение руководителем ХАССП, пересмотр с новой версией, печатная форма PDF и экспорт CSV/XLSX на языке интерфейса. **Фаза 4**: модули **A03 «Мониторинг ККТ/OPRP»** (реестр, форма записи с блокировкой оборудования с истёкшей поверкой, автоматическое несоответствие и карантин партии при выходе за предел, корректировки, графики трендов, журнал PDF/CSV/XLSX) и **A10 «Среда и холодовая цепь»** (точки по зонам, журнал T°/влажности, графики, отклонения с регистрацией несоответствия). **Фаза 5**: модуль **A04 «Прослеживаемость и отзыв»** — дерево назад (сырьё, упаковка, поставщики) и вперёд (отгрузки, клиенты), тест прослеживаемости и тестовый отзыв с таймером, отметками возврата и отчётом PDF/CSV/XLSX; превышение целевого времени регистрирует несоответствие. На странице C03 — форма отгрузки с проверками статуса партии, остатка и FEFO. **Фаза 6**: **A02 «PRP / OPRP»** — реестр программ по разделам ISO/TS 22002-1 со сроками проверок, OPRP из плана ХАССП, чек-листы периодической оценки с файлами-доказательствами (хранятся в базе, попадают в бэкап) и печатной формой; **D04 «Несоответствия и CAPA»** — регистрация, «5 почему», диаграмма Исикавы (6M), CAPA с ответственными и сроками, проверка результативности, жизненный цикл на автомате, протокол НС + отчёт CAPA. **Фаза 7**: **E01 «Отчётность и пакет для аудита»** — конструктор отчётов (источник, период, поля, группировка, предпросмотр, CSV/XLSX/PDF) и пакет для аудита за период одним PDF (титул, оглавление, план ХАССП, записи ККТ/OPRP, прослеживаемость, доказательства CAPA, дата и автор). Цифры отчётов и пакета считаются теми же запросами, что экраны модулей. **Фаза 8**: 19 модулей-каркасов на одном типовом шаблоне — панель на реальных данных, таблица с демо-данными, форма будущих полей, печатная заготовка PDF и видимая пометка «в разработке» с описанием будущего наполнения; рабочие формы на полных данных: B03 (регистрация партии с расходом сырья), C01 (смена статуса партии по автомату), C03 (отгрузка), D03 (запись поверки). E02 — пользователи и роли, журнал входов, журнал аудита с проверкой хэш-цепочки, бэкап, площадка (мультиплощадка — заготовка).

## Запуск

Нужен **Node.js 22** или новее (Windows, macOS, Linux).

```bash
npm start
```

Команда сама установит зависимости (если их нет), соберёт клиент и запустит сервер: **http://localhost:3000**.
Порт меняется переменной `PORT` (`PORT=8080 npm start`).

При первом запуске база `data/haccp.sqlite` создаётся и заполняется демо-данными автоматически.

### Вход

В демо-режиме экран входа показывает список учётных записей; пароль у всех — `demo`:
`admin`, `haccp.lead`, `technologist`, `operator`, `qa.lab`, `warehouse`, `tech.director`, `auditor`, `qa.tech` (две роли: качество + технолог).

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | порт сервера |
| `HACCP_DATA_DIR` | `data` | каталог базы и бэкапов |
| `DEMO_MODE` | `1` | список учёток на экране входа и сброс демо-данных; `0` — скрыть |
| `HACCP_FRESH` | `0` | `1` — удалить базу при старте и засеять заново |

Интернет нужен только при первой установке зависимостей. Во время работы приложение не обращается во внешнюю сеть: шрифты (включая армянские), иконки и библиотеки входят в сборку.

## Тесты

```bash
npx playwright install chromium   # один раз, нужен интернет
npm test
```

`npm test` выполняет: проверку типов → линтер → unit-тесты (Vitest) → e2e-тесты (Playwright, Chromium) → проверку чистой копии (`scripts/clean-clone.mjs`: клон во временный каталог, `npm start` без ручных шагов, вход, демо-данные, отсутствие внешних адресов в сборке; порт 3190) → обновление [`docs/03-acceptance.md`](docs/03-acceptance.md).
Имя каждого теста начинается с кода критерия приёмки (`K1` … `K26`). Скриншоты проверок — в [`docs/evidence/`](docs/evidence/).

Во всех e2e-тестах действует общая проверка: любая ошибка в консоли браузера или запрос не на `localhost` валит тест.

## Языки

Русский, English, Հայերեն — переключатель в верхней панели, без перезагрузки страницы; выбор запоминается.
Словари: `shared/i18n/{ru,en,hy}.json`, ключи одинаковые (проверяется тестом). Термины — через [`docs/glossary.csv`](docs/glossary.csv).

> **hy — требует вычитки носителем.** Армянские тексты интерфейса и глоссария подготовлены исполнителем.

## Структура проекта

```
client/    интерфейс (React + Vite): оболочка, компоненты, i18n, стили
shared/    общий код клиента и сервера: реестр 26 модулей, словари, разбор чисел, время (Asia/Yerevan)
server/    локальный сервер (Fastify + SQLite): db/ (схема), core/ (права, журнал, автоматы, целостность),
           seed/ (справочники и DEMO-данные), queries/ (общие запросы панелей и отчётов), modules/ (API)
scripts/   start.mjs (одна команда запуска), test.mjs, clean-clone.mjs, acceptance-report.mjs
tests/     unit/ (Vitest), e2e/ (Playwright), fixtures/
docs/      требования, план, нормативные ссылки, глоссарий, приёмка, скриншоты
```

## Сброс демо-данных и бэкап

- **Сброс**: кнопка ⟲ в верхней панели (роли: администратор, технолог/производство, качество/лаборатория). Перед сбросом текущее состояние автоматически сохраняется в `data/backups/`; журнал аудита продолжает хэш-цепочку прежней базы.
- **Экспорт / импорт состояния**: меню пользователя → «Резервная копия состояния» (только администратор). Импорт записывается в журнал аудита; перед импортом тоже сохраняется бэкап.
- Полностью с нуля: остановить сервер и удалить каталог `data/` (или запустить с `HACCP_FRESH=1`).

Модель данных — [`docs/02-data-model.md`](docs/02-data-model.md).

## Печатные формы

PDF формируются на сервере (pdfmake) со встроенными шрифтами Noto Sans, Noto Sans Armenian и Noto Sans Math (символы «≥», «≤») из `assets/fonts/` (лицензия SIL OFL 1.1, `assets/fonts/OFL.txt`). Язык формы — язык интерфейса.
