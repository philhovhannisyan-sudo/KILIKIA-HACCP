# CLAUDE.md — HACCP Suite

Постоянные правила проекта. Действуют в каждой сессии.

## Источники требований
- Требования: `docs/00-brief.md` — единственный источник правды. Читать перед любой фазой.
- Нормативные формулировки, номера пунктов, числовые нормативы: только `docs/regulatory-refs.md`. Из памяти не брать. Нет данных → задать вопрос, оставить `TODO(вопрос-N)`.
- Текущий план: `docs/01-plan.md`. Статус приёмки: `docs/03-acceptance.md`.
- Противоречие между файлами → остановиться и спросить.

## Порядок работы
- Одна фаза за сессию. После отчёта по фазе — **остановиться и ждать подтверждения**.
- В начале сессии: прочитать brief, plan, acceptance; определить текущую фазу; кратко сообщить, с чего продолжаешь.
- Коммит на фазу: `Фаза N: описание`. Не переписывать историю.
- Перед отчётом прогнать **все** тесты (`npm test` или команда из README), не только тесты текущей фазы. Отчёт содержит фактический вывод, а не пересказ.
- Не помечать критерий выполненным без зелёного теста.

## Архитектура (не менять без согласования)
- Локальный бэкенд, права и целостность проверяются на сервере.
- Журнал аудита: только добавление, хэш-цепочка, снимок имени и ролей на момент записи.
- Записи мониторинга, среды и журнала не изменяются: исправление — запись-корректировка.
- Жизненные циклы — конечные автоматы, описанные в данных.
- Всё работает без интернета: шрифты (в т. ч. армянские), библиотеки PDF/XLSX — локально, без CDN.
- Часовой пояс Asia/Yerevan; время записи — серверное.

## UI
- Ни одной зашитой строки в разметке: всё через словарь ru/en/hy. Пропущенный ключ — падение теста.
- Термины — через `docs/glossary.csv`.
- Числа вводятся с запятой или точкой.
- Никаких `alert` / `confirm` / `prompt` — только модальные окна приложения.
- Нет горизонтальной прокрутки на 390px; текст не обрезается ни на одном языке.
- Каркас всегда с видимой пометкой «в разработке». Не выдавать заглушку за готовый модуль.

## Данные
- Демо-значения только в seed-модуле, помечены `// DEMO`.
- Цифры панелей и отчётов считаются тем же кодом, что и в модулях.

## Чего не делать
- Мобильное приложение, PWA, интеграции, рассылки, платежи, реальная 2FA/SSO.
- Не добавлять функциональность сверх брифинга без вопроса.
- Не включать тексты стандартов ISO/BRCGS — только номера пунктов и собственные краткие названия.
